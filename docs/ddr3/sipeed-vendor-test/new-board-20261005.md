# Replacement Tang Primer 20K Dock DDR3 comparison

Test date: October 5, 2026 (America/New_York). The user attached a new Tang Primer 20K Dock and reported its DDR chip marking as `H5TQ1G63ERF PBC` (recorded literally; likely `H5TQ1G63EFR-PBC`). The vendor test detects 1 Gbit / 128 MiB.

The exact SRAM bitstream tested on the previous board was reused, without rebuilding or modifying RTL, constraints, patterns or controller configuration:

- Sipeed upstream commit: `e469df4c0c9c41824f405a8515decf24ef1e8e6f`.
- Test bitstream SHA-256: `167d04a87c0e0084204a1863f8a999f7c696d0d25ca959a82228c203470b7f50`.
- Controller: Gowin DDR3 IP; compiler: Gowin V1.9.12.04.
- UART: Sipeed Dock debugger `if01`, 115200 baud, 8N1.
- Programming: FPGA SRAM only; flash untouched.

## Result

All three fresh SRAM loads completed both fill/check stages with no reported mismatch: six successful full-range check stages in total. Each complete test finished about 48.2 seconds after starting its programming command. Captures run for 110 seconds per fresh load; the automatic reset at 100 seconds starts another cycle, but these partial cycles receive no additional pass credit. [Raw evidence and manifest](20261005T211409Z-new-board/results.json).

| Board | Fresh SRAM loads | Successful complete tests | Outcome |
|---|---:|---:|---|
| Previous board, October 1 | 3 | 0 | Every load failed the first check |
| New board, October 5 | 3 | 3 | Every load passed both check stages |

The same bitstream fails on the previous board and passes on the replacement. This favors a hardware difference in the previous assembly over a universal problem with this test image; it does not prove defective memory silicon.

This is a comparison of the complete board and Dock assemblies identified by the user; JTAG ID and the debugger's generic serial name do not uniquely identify the memory chip or board. The comparison cannot isolate the DDR silicon from board power, soldering, signal integrity, Dock connections or other hardware differences. A passing vendor test also does not qualify LiteDRAM, CPU caches, cold boots or a long-duration stress workload. The upstream second-stage `rng_inv` uses the same generated data as the first stage, so these are two full-range passes of the same pattern sequence, not complementary patterns.

The current repository already contains the October 2 correction to 128 MiB Hynix geometry in `gateware/ddr_geometry.py`; the earlier vendor-test report's discussion of a 256 MiB assumption describes the older configuration. This comparison has not run the corrected LiteX design.

Final recovery successfully loaded the retained idle SRAM image, holding DDR RESET# low, CKE low, CS# high, CK stopped and ODT low. Programming returned success and the subsequent three-second UART capture was empty. Recovery programming and UART observation are recorded in the new-board capture directory.
